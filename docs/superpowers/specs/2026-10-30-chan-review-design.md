# 缠论复盘页面与历史信号归档设计

日期：2026-10-30。代码基线：`6a1099f0f8e9804c34ea56b51b5e0b26ce6d0c57`。

## 1. 已确认目标

用户要求新增独立页面：盘后批量找出股票的一买、二买、三买，按历史日期查询；点击股票直接看图，通过当时结构、后续走势及逐根回放人工判断效果。首版不计算胜率、止盈止损或自动交易。

沿用既有 K 线风格和已固定版本的 chan.py，不引入第二套缠论算法。复盘页必须有显式导航项，避免入口只存在于侧栏展开时的顶部小按钮。

## 2. 方案选择

三种可行层级：只保存信号股票列表不能恢复当时画线；每次打开重新计算历史会受引擎、参数和行情修订影响；保存扫描输入及当时结构快照可以可靠回看。因此采用第三种：任务元数据、不可变行情输入、不可变结构快照和可分页的信号索引。

当前缠论分析页仍保持单股即时分析；复盘页消费有出处的归档，不把当前重算结果冒充过去实际生成的记录。

## 3. 页面设计

新增 `/chan-review`，导航名称「缠论复盘」，通过既有扩展 routes/navigation 注册，展开侧栏显示文字，收起显示图标。页面沿用 bg-surface、border-border 等现有令牌和 EChartsCandlestick，不增加新 UI 框架。

顶部：首次发现日期范围、日线/周线、每日归档/历史补算、股票代码或名称过滤，以及「盘后扫描」「补算历史」「任务记录」。首次打开默认展示最近一批已完成结果；没有档案时显示扫描和补算引导，不伪造信号列表。

主体为三部分：

1. 一买、二买、三买标签与各自去重后的记录数；保留原始子类型筛选。按上游 main_type 分组：1/1p、2/2s、3a/3b；列表明示子类型，不能把 1p 隐藏成完全相同的一买。
2. 股票信号列表：股票、周期、买点类型、图上发生日期、首次观测日期、来源与最新观测状态。默认按首次观测时间倒序；同股不同类型可以在多个分类出现。服务器分页，前端不把全市场历史一次载入。
3. 复盘图及详情：点击记录定位信号，显示笔、线段、中枢和原信号标记，支持上一只/下一只、图层开关、成交量、MACD。窄屏将列表与图表纵向排列。

图表提供两个明确模式：

- **当时结构**：只读取归档中该次观测已有的 K 线与结构，右侧没有未来 K 线。标出买点所在日期与实际发现日期。
- **后续走势**：在后续行情中标出原信号日期。逐根前进、后退、播放/暂停和速度选择只改变已揭示的K线范围。原归档永远保留；若展示当前重算结构，明确标识为当前结构，不能覆盖原记录。

后续行情重新复权或修订时，不直接拼接不同口径的价格。保留原图快照，后续图使用当前统一口径、按日期定位原信号并标注价格口径变化；没有明确复权映射时不把旧结构价格平移到新图。数据缺口明确展示，不能凭空补K线。

## 4. 信号档案语义

来源分为 `observed`（本系统盘后实际扫描）和 `backfill`（使用现有历史数据逐日补算）。两类默认分开查询，不能把补算时间当成当年真实观测时间。历史补算只说明在当前保存的数据版本和规则下、仅看到截至那天的数据会产生什么。

每条观测记录至少包含：

| 字段 | 含义 |
| --- | --- |
| owner_scope / run_id | 用户归属与扫描任务，服务端生成归属 |
| symbol / name / period | 标的、名称与级别，名称标明使用当前维表时的限制 |
| point_type / point_date / point_price | 上游原始买点类型、极值发生日与当时价格 |
| observed_as_of / created_at | 分析截止交易日与实际执行时间，不能互相替代 |
| first_seen / last_seen / left_censored | 可证明的首次/最近观测；窗口开始前已存在时标记左截断 |
| source / engine_revision / config_hash | 真实归档或补算、固定引擎版本及参数摘要 |
| input_hash / snapshot_id | 本次输入与原始图表快照引用 |

同一用户、来源、引擎/参数、股票、周期、原始类型和买点发生日构成信号关联键。每次观测事实不可覆盖；列表按关联键/连续出现区间归并，重复扫描不制造重复记录。几何修订保留新版本及关联关系，不悄悄修改旧快照。

新增、延续、消失的判断必须基于成功覆盖该股的连续有效扫描。失败、漏扫、停牌、行情未到位不能据此认定信号消失。信号消失后仍可查询原始记录；再次出现保留新的出现区间。初始补算窗口左侧已有的信号只可称「本范围首次观测」，不能宣称历史上第一次出现。

沿用当前公开 CBS_Point 没有独立确认标记的事实，买点全部标明「形态信号」。笔/线段/中枢按引擎 is_sure 显示实线或候选虚线。

## 5. 生成与历史补算

首版提供手动盘后扫描和历史补算，任务持久化、显示进度、可取消、失败可重试，刷新页面能接回。首版不额外创建无人值守定时任务；以后接自动盘后触发时调用同一个扫描入口。

扫描范围支持全市场股票、自选范围和明确代码列表。全市场取仓库 instruments 的股票标的，不通过代码格式猜资产类型。每个任务记录计划股票数、完成/失败/缺数据数、有效交易日期及覆盖范围；只有完整有效覆盖的日期才标记为扫描完成。

历史补算开始和结束日期由用户选择，按仓库实际交易日期推进，首版单任务最多252个观测交易日；更长范围分任务执行。每只股票读取截至任务结束日的可用标准日K并为窗口提供预热，计算输入最多2000根，记录实际预热覆盖；不足不能伪装为完整历史。退市股或历史成分不可得时明确标记股票范围限制，不能承诺没有幸存者偏差。

复用现有 chan.py 适配器，提取可逐根喂入的核心，扫描同一股票只向引擎前进一次，不对每个截止日重新跑整段历史。每个观测日只保存截至当天的状态；未来数据不能进入当时结构。每只股票处理完成后释放引擎。

只读本地已同步行情，不在批量任务中为每只股票发起外部下载。数据未同步、重复日期/股票、非法OHLC、无法稳定取得 enriched generation 时记录失败或缺数据，不静默去重选一条。输入物化和 generation 前后校验确保任务使用一致版本；变化则将任务标记需重试，不发布混杂结果。

周线沿用当前保守规则：最后一周不作为已完成证据，确认/可观察日期按下一周首根已提供交易日记录。当日未定版日K不能生成 `observed` 盘后归档；历史补算不能用未来交易日来提前确认本周结构。

## 6. 真实复用边界

已由代码确认：

- `frontend/src/custom/chan/ChanChart.tsx` 和现有 EChartsCandlestick 提供主图、结构映射、子图及定位；需要把高亮选中信号与原图/后图显示模式做成小粒度参数，不能复制整套K线实现。
- `backend/app/services/chan_analysis.py` 已调用固定版本上游，支持日/周线。提取逐根核心时保持既有 `/api/custom/chan/analyze` 返回契约和现有测试。
- `KlineRepository.get_instruments()`、`get_daily_batch(symbols,start,end,columns)`、`get_daily_asset(...)`、`latest_enriched_date()` 可供领域服务读标准行情；当前 ExtensionContext 的只读协议只有 get_name_map，不虚构批量读接口。新扩展路由沿用 request.app.state.repo 获取现有仓库，领域服务负责批量读取。
- `get_enriched_generation` 提供输入版本边界；任务复用 `shared_heavy_job_limiter` 的准入机制，默认一个计算进程，不在 API 请求线程或行情回调中跑全市场循环。
- `MiningRunStore(data_dir, namespace='chan_review')` 已支持独立命名空间、任务清单、摘要和有界事件。复用元数据部分；其 artifact 名称是有限白名单，不能假定可以直接传入 signals/snapshots。
- `task_registry` 当前只接受 backtest/mining/walkforward/robust_optimizer，不存在 chan_review 类型；首版通过自身任务列表恢复，不伪造已有任务注册能力。
- `JsonReportStore` 会裁剪旧报告，不适合长期档案。使用窄职责的缠论归档模块保存不可变快照及分区信号索引，复用 `fs_utils.atomic_write_text/atomic_write_parquet`，不复制另一套数据仓库或通用任务框架。

## 7. 存储、隔离与接口

运行数据位于 `data/research/chan_review/`。任务元数据由现有 MiningRunStore 管理；新增归档模块负责按任务保存标准OHLC输入、压缩JSON结构快照及 Parquet 信号索引。输入按内容哈希去重，每个观测快照引用同一输入的截止位置，避免每个信号重复保存三年行情。全部路径由服务端受约束的 ID 构造，拒绝任意路径；采用临时文件和原子替换，写入失败不把任务标记成功。

通过既有后端扩展注册 `/api/custom/chan-review`：

- `POST /runs` 创建扫描/补算任务，传来源、范围、周期、起止日期。
- `GET /runs`、`GET /runs/{id}` 查询持久任务及进度。
- `POST /runs/{id}/cancel` 请求取消。
- `GET /signals` 按日期、类别、周期、来源、股票分页查询，支持首次观测日与发生日两种日期语义。
- `GET /signals/{id}` 返回原始观测详情与快照引用。
- `GET /snapshots/{id}` 返回不可变当时行情和结构；后续走势另外通过仓库服务读取，不能改变归档。

上述均为待实现接口，尚不存在。前端请求放入 api.ts，查询键放入 queryKeys.ts；任务推进只失效所属用户和任务的列表/详情，不清空现有行情缓存。不引入新的数据库迁移或 SSE 协议。

多用户沿用 `request.state.current_user.id` 获取 owner_scope；未认证多用户请求拒绝，不能回退 standalone。任务、信号、快照及取消操作均校验归属，跨用户返回404。后台任务显式携带服务端已验证的归属。standalone 模式使用独立固定命名空间，不能与多用户目录混淆。

任务单写者锁覆盖整个写任务，默认一个工作进程并沿用重任务准入。进程退出后未完成任务标记 interrupted，保留已完成检查点；同参数再次执行校验数据版本后接续，版本不同另起任务。首版不自动删除档案、不新增任意文件下载/导入功能。

## 8. 验证与交付标准

1. 固定行情产生真实的 B1/B2/B3 各类型样本；验证分类、原始子类型保留、重跑幂等、窗口左截断标记、信号消失后档案仍在。
2. 截断输入的结果与对应历史快照一致；发生日、观测日和执行时间分开。周线跨年、未结束周、未收盘当日、停牌及缺行情不能提前产生可见信号。
3. 引擎或参数变化保留原快照；行情复权/修订不会把不同口径直接拼接；原图模式不执行会覆盖档案的当前重算。
4. 全市场只走仓库批量读取，重任务可取消、刷新重连，失败不伪装成功，重复行情明确报告；generation 变化拒绝提交混合快照。
5. 覆盖存储原子性、进程中断、检查点、路径穿越、用户隔离、权限缺失和非法输入。
6. 页面覆盖无档案、加载、错误/重试、任务进度、分类/日期/周期切换、切股不串图、上一只/下一只、原图/后图、逐根前进与后退。
7. 验证导航展开/收起/窄屏、明暗主题及既有缠论分析页回归；运行相关 pytest、Ruff、Vitest、`pnpm build` 和 `git diff --check`。无法完成的真实界面验证如实说明。
8. 完成后合并当周周报；未经本次单独要求不自动提交、推送或部署。此前一次发布授权不等于本新页面自动发布授权。
