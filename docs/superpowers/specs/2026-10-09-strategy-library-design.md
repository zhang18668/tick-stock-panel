# 策略库与周期回测对比设计

日期：2026-10-09

## 目标与成功标准

新增一个策略库页面，集中展示当前可用的内置策略及其规则说明，并以最近 3 个月、6 个月、1 年三个滚动周期的回测汇总作横向比较。使用者能快速看出策略表现、查看统计口径与策略细节，并手动把策略归入自己命名和排序的档位（例如“拉”“夯”）。数据不足或回测失败时必须明确标注，不能将缺失值当成零或据此自动分组。

策略源码以当前服务器上可取得的源码为准；页面对本地不可用的策略显示明确状态。服务器源码属于用户数据，不提交进仓库。

## 已确认的产品决策

- 使用现有前端扩展路由和导航注册新增完整页面。
- 档位名称、顺序由用户自行定义；策略通过手动操作分组，未分组策略显示在“未分组”区域。绩效指标只供判断，不触发自动分组。
- 每个策略提供规则/说明、参数、风险设置、执行方式等详情。
- 显示最近 3 个自然月、6 个自然月、12 个自然月的滚动回测窗口；每个窗口都以最新可用交易日结束。
- 批量回测可覆盖全部可用策略，也可针对单个策略重跑。运行进度、当前策略与周期、取消、失败及重试状态均可见；单项失败不阻断其余项目。
- 保留完成窗口的汇总结果，供比较和后续查看；不持久化全部逐笔明细。

## 页面与交互

策略库页分为顶部回测控制/数据更新时间、用户定义的档位区域、未分组区域和策略详情视图。策略卡片展示名称、简述、分组、最近成功回测时间及三个周期的关键结果；用户可查看完整指标、数据窗口、策略配置快照和错误状态。卡片可在不同档位间手动移动，档位可创建、重命名、排序和删除。删除档位时，其策略回到未分组，避免丢失策略或分组归属。

比较指标包括总收益率、最大回撤、Sharpe、胜率、盈亏比、基准收益、超额收益和交易次数，并注明周期起止日期、数据更新时间以及有效/缺失状态。排序与筛选只改变展示，不改变分组。指标使用现有策略回测返回的统计口径；若现有统计项无法可靠获得，则显示不可用及原因，不在前端另算金融指标。

## 后端与数据流

使用现有策略发现和策略回测引擎，不复制策略执行逻辑。扩展 `/api/strategies` 的详情输出以补充已在策略模块定义的 `RULES` 和执行元信息，并保持旧字段和调用兼容。回测任务由独立的策略库任务管理器串行调度，复用现有策略回测 worker/engine、数据 provider、参数、费用与风控口径，并遵守 HeavyJobLimiter 等现有并发限制。

一次全量更新为每个可用策略生成 3 个窗口任务；共享同一个最新可用交易日作为窗口结束日。任务记录状态、进度、当前策略/周期、取消请求、错误和重试次数。取消应在当前回测安全退出后停止后续任务。单项错误隔离并允许重试；不可用源码、缺失数据能力、数据不足和窗口限制都要以结构化状态返回。

每个成功窗口保存紧凑结果摘要、窗口实际起止日、回测配置快照标识、源码/策略指纹和完成时间。数据按用户隔离：复用 standalone 的 preferences 持久化和多用户 settings context；将新个人偏好字段加入 `_USER_PREFERENCE_KEYS`。不得覆盖其他用户或现存偏好。保存采用现有 merge-write 语义；失败时保留上一份有效结果。

## 滚动窗口、能力及限制

以最新可用交易日为共同结束日，按日历月回溯 3、6、12 个月，再使用现有交易日/行情数据边界确定实际可回测区间。界面同时展示请求窗口和实际可用窗口。窗口定义必须由后端统一计算，前端不得自行推算交易日。

保留现有数据源 provider 抽象和能力声明。分钟策略需要 provider 能力及完整窗口数据；缺失时显示不可回测原因，不能静默退化为日线结果。现有 `backtest_range_guard` 若启用且拒绝超过 186 天的请求，1 年窗口应显示清晰限制状态；不绕过该保护。任务使用有界内存和串行执行，避免同时启动约 120 个回测造成资源峰值。

## API 形态与失败语义

新增策略库任务 API：创建/启动全量或单策略更新、读取任务状态和结果、请求取消、对失败项重试，以及管理用户分组和归属。接口需有明确的 schema、状态枚举和错误码；所有写操作应用当前用户身份与权限上下文。任务结果采用稳定 ID 和有限保留策略，避免无限累积；重复启动应明确拒绝或复用运行中任务，不能并行重复占用回测资源。

失败按策略/窗口隔离并持久化原因。任务级失败（初始化、存储或未预期异常）应标明已完成、失败和未执行项目；不能把部分结果伪装成全量完成。后端退出造成的运行中任务应在恢复时标记中断，已保存结果继续可读。

## 验证要求

实现阶段至少验证：策略详情兼容性和真实规则字段；窗口边界与共同结束日；单项失败隔离、取消、重试和重复启动；provider 能力缺失与 1 年窗口保护；单用户及多用户偏好隔离、merge-write 与历史数据兼容；手动分组 CRUD 和删除分组后的策略归属；前端加载、空、错误、部分完成、窄屏及比较展示。验证仅报告实际执行的命令和结果。

## 范围与升级注意

首版不自动推荐档位、不新增策略执行算法、不生成新的策略源码、不存逐笔回测明细，也不绕过已有回测保护。优先采用扩展路由和独立后端扩展；只有真实调用链表明无法通过现有扩展契约完成时，才对核心源码作最小必要修改。重点复核策略发现、回测 worker、HeavyJobLimiter、preferences 多用户隔离及扩展注册兼容性。
