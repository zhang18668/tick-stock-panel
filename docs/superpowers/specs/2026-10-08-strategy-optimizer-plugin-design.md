# 策略自适应优化插件设计

## 1. 背景与目标

Tick Stock Panel 已具备策略参数优化、策略回测、步进样本外验证、独立 worker、任务取消、重任务限流和部分持久化任务能力。当前缺少一个面向用户的完整工作流：用户主动指定一个已有策略后，系统在后台分轮分析合理参数区域，并输出经过样本外验证的 Top 3 推荐参数。

本功能以源码内插件形式接入，目标如下：

- 用户主动启动一次优化任务，任务完成或达到停止条件后结束，不创建定时任务。
- 优化策略已经声明的参数，并允许组合系统中已注册的买入、卖出信号。
- 优化器只能在策略声明的硬边界和约束内搜索，不修改或生成 Python 策略代码。
- 以收益为第一优先级的综合评分评价候选，并通过步进样本外验证降低过拟合风险。
- 输出有差异且可解释的 Top 3 候选。
- 只保存推荐结果，不自动修改、覆盖、发布或启用原策略。
- 复用现有策略、回测、worker、矩阵缓存和重任务限流能力，不实现第二套回测引擎。

## 2. 范围

### 2.1 首版包含

- 独立的前端插件页面与导航入口。
- 独立的后端插件 API、后台任务编排和结果存储。
- 整数、浮点、布尔和枚举参数的自适应搜索。
- 已注册买入、卖出信号的有限组合搜索。
- 参数硬边界、步长、枚举值和跨参数约束。
- 可编辑的评分权重、风险门槛、收敛规则、轮数和每轮候选数。
- 任务进度、取消、异常中断识别和人工恢复。
- Top 3 参数、综合评分、分项指标、逐折摘要及参数差异对比。

### 2.2 首版不包含

- AI 修改、生成或自动修复策略源码。
- 自动应用、自动发布或自动替换原策略。
- 定时、每日或每周自动优化。
- 自动实盘或模拟盘下单。
- 删除历史优化任务。
- 贝叶斯优化、遗传算法或可安装的通用优化器市场。
- 对没有完整参数契约的策略猜测搜索范围。

## 3. 二次开发分级

整体采用“L2 插件主体 + 最小 L3 核心接线”：

- 前端通过现有静态路由与导航注册机制接入，属于 L2。
- 后端通过现有自定义扩展路由、启动钩子和关闭钩子接入，属于 L2。
- 当前 `ExtensionContext` 只提供 `data_dir` 和只读仓库，未公开策略发现、参数契约读取和候选回测能力。核心需增加一个小粒度、版本化的优化服务契约及默认实现，属于最小 L3 改动。

插件不得继承或覆盖 `StrategyEngine`、`BacktestEngine`、`StrategyBacktestService` 等大型编排对象。核心契约负责把现有能力以稳定、受限的方式提供给插件。

## 4. 总体架构

### 4.1 组件

1. `StrategyOptimizerPage`
   - 选择可优化策略。
   - 编辑搜索、评分、风控和停止规则。
   - 创建任务、查看进度、取消或人工恢复任务。
   - 对比 Top 3 推荐结果。

2. 插件 API Router
   - 校验请求和所有权上下文。
   - 调用任务管理器。
   - 返回任务、候选和增量事件。
   - 不在 API 层执行回测或大规模计算。

3. `OptimizationJobManager`
   - 管理状态迁移、取消事件和 worker 生命周期。
   - 通过现有重任务限流器获取执行槽位。
   - 控制同进程并发并在关闭时释放资源。

4. `AdaptiveSearchService`
   - 生成每轮候选。
   - 校验参数约束。
   - 根据上一轮结果缩小高潜力区域，同时保留探索候选。
   - 计算评分、判断收敛并选出 Top 3。

5. 核心 `StrategyOptimizationGateway`
   - 列出可优化策略。
   - 返回规范化参数与信号契约。
   - 使用现有 worker 提交候选回测和步进样本外验证。
   - 对插件隐藏策略加载、矩阵构建、缓存和成交模拟内部细节。

6. `OptimizationRunStore`
   - 原子持久化任务清单、事件、轮次、候选及 Top 3。
   - 校验路径和 schema，隔离损坏记录。

### 4.2 依赖方向

```text
前端插件页面
  -> 插件 API Router
  -> OptimizationJobManager
  -> AdaptiveSearchService
  -> StrategyOptimizationGateway（核心稳定契约）
  -> 现有 StrategyEngine / Backtest worker / WalkForward / HeavyJobLimiter
  -> 标准化仓库与 provider 数据
```

插件只能通过网关提交金融计算，不得直接读取数据源 SDK、绕过标准化仓库或自行模拟成交。

## 5. 核心扩展契约

核心新增小粒度、只读的版本化协议。具体 Python 命名可在实施计划中结合现有类型确定，但语义必须包含：

- `list_optimizable_strategies()`：返回策略 ID、名称、资产类型、执行后端、是否可优化及不可优化原因。
- `get_optimization_contract(strategy_id)`：返回规范化参数定义、允许的买卖信号、约束和策略版本摘要。
- `evaluate_candidates(request, candidates, progress_cb, cancel_event)`：通过现有 worker 和回测服务批量评估候选。
- `validate_oos(request, candidates, progress_cb, cancel_event)`：对入围候选执行完整步进样本外验证。

网关请求必须显式携带策略 ID、资产类型、日期范围、交易成本、成交选项、参数快照、信号组合、随机种子和数据指纹。返回值必须区分业务不可计算、候选无效、取消、worker 故障和系统故障。

没有安装插件时，新增网关不得改变现有策略、回测、缓存或启动行为。插件与网关分别维护 `api_version`；破坏性变化提升主版本。

## 6. 参数与信号契约

每个可优化参数必须声明：

- 稳定参数名和用户可读标签。
- 类型：整数、浮点、布尔或枚举。
- 默认值。
- 最小值、最大值和步长，或明确的枚举集合。
- 是否允许优化。
- 可选的分组和说明。

策略还可以声明跨参数约束，例如：

- 短周期必须小于长周期。
- 止损幅度必须小于止盈幅度。
- 某参数只有在对应信号启用时才生效。

买入、卖出信号只能来自现有注册表。策略契约明确允许加入、移除或组合的信号集合、最大组合数量和互斥关系。优化器不得自行创造信号 ID，也不得组合资产类型不兼容的信号。

参数契约不完整、边界非法、默认值越界或约束互相冲突时，策略标记为不可优化。系统不得根据历史值或名称猜测范围。

## 7. 自适应搜索

### 7.1 首轮

首轮覆盖完整允许范围，候选来源包括：

- 当前默认参数。
- 合法边界和代表性中间点。
- 按固定随机种子生成的分层采样组合。
- 合法的买入、卖出信号组合。

候选生成后先执行纯约束校验，非法组合不占用回测预算。

### 7.2 后续轮次

每轮完成后，按综合评分保留高潜力候选。下一轮：

- 约 80% 候选在高分参数区域附近生成，并逐轮缩小连续参数范围。
- 约 20% 候选继续从完整合法空间探索，降低过早陷入局部最优的风险。
- 离散参数根据高分候选频率提高采样权重，但不提前永久删除仍合法的取值。
- 已评估的完整参数和信号组合不重复执行。

搜索器必须在固定输入、固定数据指纹和固定随机种子下可复现。

### 7.3 默认停止规则

- 连续 3 轮最佳综合评分提升不足 1%，判定收敛。
- 最多运行 10 轮。
- 每轮最多评估 50 组参数。
- 用户请求取消。

规则可编辑，但服务端必须设置有限且可测试的最大轮数、每轮候选数、总候选数和参数维度上限，禁止无界任务。达到任一停止条件后进入最终验证阶段；取消任务不生成新的推荐结论。

## 8. 回测与样本外验证

候选评估复用现有回测矩阵、worker 和成交模拟。信号生成与成交模拟继续保持分离，并遵循：

- 只能使用目标交易日当时已公开、可获得的数据。
- 股票 T+1、手续费、印花税、滑点和涨跌停不可成交规则不得被优化配置绕过。
- 日线信号不得描述为信号触发瞬间成交。
- 分钟成交只有在完整分钟数据覆盖所需窗口且 provider 能力可用时启用。
- 矩阵缓存键必须覆盖策略版本、参数、信号组合、资产类型、完整 fold 窗口、数据 generation、日期和所有影响矩阵的输入。

训练区间用于自适应搜索。入围候选必须使用现有步进样本外验证能力进行完整验证，最终排名只使用样本外指标。无法形成有效样本外折时任务失败，不用样本内成绩替代。

## 9. 综合评分与门槛

默认权重为：

| 指标 | 权重 | 方向 |
| --- | ---: | --- |
| 样本外收益率 | 55% | 越高越好 |
| 最大回撤改善 | 20% | 回撤越低越好 |
| 胜率 | 15% | 越高越好 |
| 有效交易次数 | 10% | 达到可信区间后收益递减 |

权重可编辑，但总和必须为 100%。收益始终是默认且最高权重指标。

各指标在同一最终候选集合内使用预先定义、可测试的稳健规范化方式转换为 `[0, 1]`。不得让异常极值任意改变其他候选的方向。交易次数使用饱和评分，避免高频交易通过无限增加次数刷分。

任务还包含两个可编辑硬门槛：

- 最大允许样本外回撤。
- 最低有效样本外交易次数。

未通过硬门槛的候选不得进入 Top 3，无论综合评分多高。指标缺失或非有限值视为不可计算，不得转换成零后继续排名。

## 10. Top 3 选择

通过完整样本外验证和硬门槛的候选按综合评分降序排列。为避免返回三个实质相同的答案，选择过程增加多样性过滤：

- 完整参数和信号组合相同的候选只保留一项。
- 参数距离低于阈值且交易记录高度相似时，只保留分数最高者。
- 多样性阈值写入任务配置和结果，保证可解释与复现。

若只有一至两个有效且有差异的候选，则按实际数量返回，并明确标记“有效推荐不足 3 个”。不得使用未通过门槛的候选凑数。

每个推荐必须展示参数与原策略的差异、信号变化、综合评分、分项指标、逐折摘要、交易数量、停止原因和数据指纹摘要。

## 11. API 设计

后端插件使用 `/api/custom/strategy-optimizer` 命名空间：

- `GET /strategies`：列出支持优化的策略和不可优化原因。
- `GET /strategies/{strategy_id}/contract`：读取参数、信号及约束契约。
- `POST /runs`：创建并启动任务，返回稳定 `run_id`。
- `GET /runs`：列出历史任务。
- `GET /runs/{run_id}`：读取配置、状态、当前轮次、进度、摘要和 Top 3。
- `GET /runs/{run_id}/events`：返回 SSE 增量事件和心跳。
- `POST /runs/{run_id}/cancel`：请求取消。
- `POST /runs/{run_id}/resume`：人工恢复允许恢复的任务。
- `GET /runs/{run_id}/candidates/{candidate_id}`：读取候选参数、逐折指标和交易摘要。

任务创建请求必须使用严格 schema，拒绝未知字段、非有限数字、非法日期范围、越界预算、未知策略、未知信号和不满足约束的固定参数。API 只做校验和编排，不执行同步重计算。

SSE 断开不取消任务。客户端通过最后事件 ID 增量恢复；事件超出保留窗口时，客户端重新读取任务快照。

## 12. 任务状态与生命周期

状态机为：

```text
queued -> running -> succeeded
                  -> failed
                  -> cancelling -> cancelled

应用异常退出：queued/running/cancelling -> interrupted
人工恢复：interrupted/可恢复的 failed -> queued
```

同一任务的状态迁移必须原子、可验证，非法迁移被拒绝。页面关闭或 SSE 断开不改变状态。

人工恢复必须重新校验策略版本、参数契约和数据指纹：

- 输入完全一致时，可从最后一个完整轮次继续。
- 输入已变化时，拒绝原地续跑，并提示用户创建新任务。

插件关闭钩子发出取消信号并在有限宽限期内等待。后台线程或子进程不得阻止应用退出。重启时没有存活 worker 的活动任务统一标记为 `interrupted`，不自动重跑。

## 13. 持久化

运行数据保存在应用数据目录下的独立插件目录，不进入 Git：

```text
strategy_optimizer/
  runs/<run_id>/
    manifest.json
    events.jsonl
    rounds.parquet
    candidates.parquet
    top3.json
```

- `manifest.json`：schema 版本、状态、任务配置、策略摘要、数据指纹、算法版本、随机种子和时间戳。
- `events.jsonl`：有界保留的状态与进度事件。
- `rounds.parquet`：每轮搜索区域、预算、最佳分数和收敛信息。
- `candidates.parquet`：候选参数、信号、状态、分项指标和失败类别。
- `top3.json`：最终推荐的紧凑快照。

所有 JSON 写入使用临时文件、刷盘和原子替换。路径必须限制在任务目录内，拒绝路径穿越。详细交易流水不在事件中重复存储；若复用现有回测结果存储，则只记录稳定引用和摘要。

任务指纹至少覆盖：

- 策略 ID、源码或定义摘要、参数契约摘要。
- 买入、卖出信号注册摘要。
- 数据 generation、资产类型、日期范围和标的范围。
- 成交模式、费用、税费和滑点。
- 评分、门槛、搜索、收敛和多样性配置。
- 随机种子、优化算法版本和回测方法版本。

旧 schema 结果允许只读展示。新版本不得无提示地续跑旧算法任务。

## 14. 错误与隔离

- 策略不存在、不可优化或契约非法：拒绝创建任务。
- 数据不足、日期缺口或无法形成有效样本外折：任务失败且不生成推荐。
- 单个候选非法或回测失败：记录结构化失败原因，继续其他候选。
- 有效候选不足 3 个：返回实际数量并显示警告。
- 所有候选失败或连续系统性 worker 故障超过阈值：终止任务并标记失败。
- worker 超时或取消：在宽限期后使用现有强制退出机制，记录退出原因。
- 持久化文件损坏：隔离该任务并返回可定位错误，不影响其他任务和应用启动。
- 插件加载、启动或关闭失败：记录错误，不影响原有策略、回测和其他页面。
- provider 缺少所需数据能力：明确拒绝或降级为契约允许的日线模式，不静默换用错误数据。

## 15. 缓存、并发与性能

- 复用现有市场数据矩阵缓存和 worker 进程；同一任务内相同完整输入不得重复构建矩阵。
- 缓存键包含每个 fold 的完整窗口及所有影响结果的输入。
- 任务通过现有重任务限流器获取槽位，不绕过全局资源限制。
- API、任务线程和 SSE 读取共享状态时使用锁、不可变快照或原子替换。
- 不在持锁期间执行回测、网络请求或大文件扫描。
- 进度事件和内存候选集合有明确上限。
- 没有活动任务时不运行后台计算。

插件只读原策略和现有策略缓存，因此创建、运行、取消或完成优化任务不触发策略结果缓存失效，也不修改监控实例。未来增加“应用推荐”功能时必须单独设计持久化、运行时实例、策略缓存、监控和前端查询失效链路。

## 16. 前端交互

插件注册独立“策略优化”路由和导航项。页面包含：

1. 策略选择与可优化状态。
2. 参数范围、信号组合和约束的只读摘要；允许在硬边界内收紧本次搜索范围。
3. 评分权重、最大回撤、最低交易次数、收敛阈值、最大轮数、每轮候选数和随机种子。
4. 数据范围、资产类型和交易成本。
5. 启动确认，其中明确说明“只生成推荐，不修改原策略”。
6. 当前轮次、已完成候选、最佳分数变化、失败分类和取消按钮。
7. Top 3 横向对比，包括相对原策略的参数差异、收益、回撤、胜率、交易次数、综合评分和逐折稳定性。

页面必须覆盖加载、空数据、不可优化、配置错误、排队、运行、取消中、已取消、中断、失败、有效候选不足和成功状态。窄屏下 Top 3 改为纵向卡片，不依赖无法操作的宽表格。

首版不提供“应用参数”按钮，避免用户误以为推荐已生效。

## 17. 测试与完成标准

### 17.1 单元与契约测试

- 参数类型、默认值、边界、步长、枚举及跨参数约束。
- 未声明参数、未知信号、无效组合和不兼容资产类型。
- 首轮覆盖、区域收缩、20% 探索、去重和随机种子复现。
- 连续三轮提升不足 1%、最大轮数和取消停止。
- 权重总和、指标方向、规范化、交易次数饱和评分和硬门槛。
- Top 3 多样性、少于三个候选和全候选失败。
- 网关默认实现、插件未启用、版本不兼容和加载失败隔离。

### 17.2 回测正确性测试

- 信号日与成交日对齐。
- T+1、手续费、印花税、滑点和不可成交规则。
- 日线与分钟模式的数据能力和缺口行为。
- 步进样本外无未来函数。
- 每个 fold 的完整矩阵覆盖及缓存键差异。
- 最终排名只使用样本外指标。

### 17.3 任务与存储测试

- 所有合法和非法状态迁移。
- 页面断开不取消、显式取消、超时、worker 退出和应用关闭。
- 重启恢复为 `interrupted`，输入一致时人工续跑，输入变化时拒绝续跑。
- 原子写入、并发读取、损坏记录隔离、路径穿越拒绝和旧 schema 只读。
- 重任务限流与多任务排队。

### 17.4 API 与前端测试

- API 成功、无数据、未知字段、越界配置、未知策略和内部失败响应。
- SSE 增量事件、心跳、重连和事件窗口过期。
- 前端所有状态、取消交互、规则编辑、Top 3 对比和窄屏布局。
- 前端 API 类型及集中查询键。

### 17.5 最低验证命令

实施完成时至少执行受影响后端模块的定向 `pytest`、对应 Ruff 检查、前端测试与 `pnpm build`、`git diff --check` 和最终 `git status`。实际命令和结果必须在实施交付中列出，不得用设计预期代替验证结果。

## 18. 验收条件

- 用户能选择一个契约完整的现有策略并成功启动后台优化任务。
- 任务按照可编辑规则分轮搜索，在预算或收敛条件满足时停止。
- 固定输入和随机种子可复现候选及排名。
- 最终只按样本外综合评分返回最多三个有差异且通过硬门槛的候选。
- 页面、API、运行时和文件系统均没有修改原策略或自动应用推荐的路径。
- 取消、异常退出、恢复和插件失败不会破坏原有策略、回测或应用生命周期。
- 未启用插件时现有功能与行为不变。

## 19. 后续扩展

只有出现明确需求并单独完成设计评审后，才考虑：

- 贝叶斯或遗传算法搜索器。
- 定时优化。
- 推荐候选的人工发布工作流。
- 多策略组合优化。
- 与模拟盘观察期联动。

这些能力不属于首版，当前设计不预留可绕过人工确认的自动替换入口。
