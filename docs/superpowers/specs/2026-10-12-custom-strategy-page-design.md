# 自定义策略页面设计

日期：2026-10-12

## 目标与成功标准

保留现有 `/backtest` 回测页及其按策略来源划分的固定分组，新增一个独立的“自定义策略”页面。新页面复用现有策略回测能力，但策略选择区域按照策略库中由用户维护的分组、顺序和归属展示。

完成后应满足：

- `/backtest` 的入口、交互和固定来源分组保持不变。
- 新页面通过前端扩展路由注册，建议路径为 `/custom-strategies`，导航名称为“自定义策略”。
- 新页面复用 `StrategyBacktest`、现有策略 API、回测任务状态、参数编辑和结果展示，不复制回测业务逻辑。
- 新页面显示“全部”“未分组”以及策略库中的用户分组；用户分组顺序与策略库一致。
- 策略库分组加载失败时给出明确提示，同时保留“全部”视图，使用户仍可选择策略并运行回测。
- 不新增或改变后端 API、策略执行契约、金融计算口径与缓存语义。

## 方案分级与边界

本需求按 L2 二次开发处理：完整页面使用当前已经实现的前端扩展路由和导航注册；为了复用核心回测主体，对 `StrategyBacktest` 增加一个小粒度、可选的展示模式参数。

该参数只决定策略选择器如何分组，不改变以下行为：

- 策略列表的来源与资产类型过滤。
- 策略详情读取、参数覆盖和配置保存。
- 回测任务启动、停止、恢复和进度展示。
- 数据能力检查、日期范围、成交规则和风控参数。
- 回测结果、交易记录、归因及导出。

现有插槽不适合本需求。当前开放插槽均不位于回测页；新增公共插槽会引入新的长期契约，而本需求只有一个已知扩展页面和一种分组差异。使用可选模式参数能够以更小范围完成复用，不提前建设通用替换框架。

## 页面与组件结构

在 `frontend/src/custom/strategy-library/` 下新增自定义策略页面组件，并把页面路由与导航注册到现有 `strategy.library` 扩展中。扩展继续作为策略库相关页面的统一入口，不新增第二套扩展加载机制。

建议结构：

```text
strategy.library 扩展
├── /strategy-library      策略库与分组管理
└── /custom-strategies     按策略库分组的策略回测页面
                             └── 复用 StrategyBacktest
```

自定义策略页面负责页面级标题、说明和分组数据查询；`StrategyBacktest` 仍负责回测主体。为避免页面复制，`StrategyBacktest` 增加可选的分组模式或等价的小粒度属性：

```ts
type StrategyGroupingMode = 'source' | 'library'
```

默认值为 `source`。现有 `/backtest` 不传该属性，继续使用“全部 / 自定义 / AI / 叠加 / 内置”。新页面传入 `library`，策略选择器读取策略库分组。

具体实现可以把分组映射提取为同文件内纯函数或邻近的小模块，前提是测试确实需要独立调用。不得为了单次使用建立新的通用策略选择框架。

## 数据流与分组规则

策略清单继续通过现有 `api.screenerStrategies(assetType, 'all')` 和 `QK.screenerStrategies` 获取。策略库分组继续通过现有 `/api/strategy-library`、`strategyLibraryApi.library` 和 `QK.strategyLibrary` 获取。两者分别保持现有缓存键和刷新语义，不建立平行缓存。

新页面的数据流为：

```text
策略列表查询 ───────────────┐
                            ├─> 按策略库分组映射 ─> StrategyBacktest 策略选择区
策略库 groups 查询 ─────────┘

StrategyBacktest 其余状态 ─────> 现有回测任务与结果链路
```

分组规则如下：

1. “全部”始终排在首位，包含当前资产类型下全部可用策略。
2. 策略库用户分组按 `order` 升序排列；`order` 相同时保持接口返回顺序或使用稳定 ID 排序，避免界面漂移。
3. “未分组”包含未出现在任何有效策略库分组 `strategy_ids` 中的当前可用策略。
4. 分组中引用已删除、当前资产类型不适用或当前策略列表不存在的策略 ID 时忽略该引用，不生成空策略对象。
5. 若历史异常数据令同一策略出现在多个分组中，展示应遵循策略库当前页面的单归属语义：使用第一个有效分组，后续重复归属忽略。实现不得静默修改服务器数据。
6. 允许显示空的用户分组，并在选中后显示“当前分组暂无策略”，使页面忠实反映策略库配置。

策略库分组变更后，`QK.strategyLibrary` 失效与刷新沿用现有策略库页面行为。用户返回或重新进入自定义策略页面时，应读取共享缓存中的最新分组；不额外写入本地存储。

## 加载、错误与回退

策略列表仍沿用现有加载和空状态。策略库分组模式新增以下状态：

- 分组加载中：策略列表可以继续加载；选择器显示轻量的分组加载状态。
- 分组加载成功：按上述规则展示全部分组。
- 分组加载失败：在选择区显示可恢复的提示和重试入口；选择器回退为仅有“全部”的视图，不阻断策略选择、详情读取或回测运行。
- 策略列表失败：沿用现有策略列表错误处理，不使用策略库数据伪造策略。

回退只影响展示，不改变策略定义或回测输入。分组错误不得被解释为“所有策略均未分组”，避免把请求失败伪装成有效业务状态。

当当前选中的用户分组在刷新后被删除时，选择器回到“全部”。当前选中的策略若仍存在则保留；策略本身不存在时，沿用 `StrategyBacktest` 当前的孤儿状态清理逻辑。

## 类型和兼容性

优先复用 `frontend/src/custom/strategy-library/api.ts` 中的 `StrategyGroup` 与 `StrategyLibrary` 类型，不在核心 API 文件中复制同名契约。若直接从扩展目录导入类型会造成核心模块反向依赖，则把只包含稳定数据形状的共享类型移动到合适的前端公共类型模块，并由策略库 API 与回测组件共同引用；不得让核心回测组件直接依赖扩展页面组件。

`StrategyBacktest` 的新增属性必须可选并具有保持现状的默认值。因此所有现有调用方不修改也能继续编译和运行。新页面只是现有回测主体的第二个挂载点，不改变后端请求载荷。

扩展路由使用当前 `FrontendExtension` 契约注册。路由 ID、导航 ID 和路径保持全局唯一；扩展加载失败时由现有注册表隔离，不影响核心 `/backtest` 页面。

## 缓存、性能与状态隔离

本设计新增一次策略库查询，但复用 `QK.strategyLibrary` 和 TanStack Query 缓存。访问过策略库页面后，新页面通常直接命中共享缓存；不得在每个策略按钮或分组内重复请求。

策略分组映射使用 `useMemo` 或等价的纯计算，只在策略列表或分组数据变化时重算。计算复杂度以策略数量与分组引用数量线性增长，不进入后端实时行情或回测计算热路径。

`StrategyBacktest` 当前会通过本地存储恢复最近一次策略及部分回测配置。两个页面复用同一回测工作区和全局任务状态，因此首版明确采用共享状态语义：从任一入口启动或恢复的是同一个策略回测任务，不并行创建第二套任务管理。分组页签选择属于展示状态，不写入现有回测配置。

## 测试与验证

实现阶段先增加能够证明分组行为的前端测试，再修改组件。最低覆盖：

- `source` 默认模式仍显示原有固定分组。
- `library` 模式按策略库顺序显示“全部”、用户分组和“未分组”。
- 用户分组正确筛选策略，未分组计算正确。
- 无效策略 ID 和重复归属不会产生重复按钮或异常。
- 空分组显示空状态。
- 分组加载失败时显示错误提示，并可在“全部”中选择和运行策略。
- 分组被删除后回到“全部”，现存策略选择保持稳定。
- `/custom-strategies` 路由和导航能够通过扩展注册加载。
- `/backtest` 未传新属性时行为不变。

最低验证命令：

```bash
cd frontend
pnpm test -- <受影响的测试文件>
pnpm build

cd ..
git diff --check
git status --short --branch
```

如项目测试脚本不支持按文件执行，应使用仓库实际可用的等价命令，并在完成说明中记录真实命令和结果。可见改动还需人工检查常用桌面宽度和窄屏下的分组横向滚动、文字截断、空状态及错误提示。

## 预计修改范围

实现预计涉及：

- `frontend/src/pages/backtest/StrategyBacktest.tsx`：增加可选分组模式和策略库分组展示接线。
- `frontend/src/custom/strategy-library/`：新增自定义策略页面，并在现有扩展中注册路由和导航。
- 邻近前端测试文件：覆盖分组映射、失败回退和扩展页面渲染。
- 必要时增加一个只承载共享类型或纯分组函数的小文件；只有依赖方向或测试隔离确实需要时才新增。

不修改后端、策略文件、用户数据、回测引擎、查询键定义或持久化格式。若实现阶段发现当前策略库 API 无法在新页面复用，必须停止并重新评估，而不是新增平行接口。

## 非目标与升级注意

首版不提供策略库分组的创建、改名、排序或删除操作；这些操作继续在策略库页面完成。新页面不自动给策略分组，不按回测表现动态调整分组，不改变一个策略只属于一个策略库分组的现有语义，也不新增权限模型。

未来合并上游时重点复核 `StrategyBacktest` 的属性和策略选择区域。如果核心回测页重构，应保留默认 `source` 模式，并确认扩展页面只依赖公开的可选属性和共享数据类型。若后续出现多个扩展需要替换策略选择器，再基于真实用例评估正式插槽；本次不提前引入该契约。
